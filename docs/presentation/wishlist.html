01 / Идея и возможности

Проблема выбора подарка

В переписке легко потерять желания и договорённости

У организатора

Ссылки на подарки разбросаны по сообщениям. Приходится повторно объяснять, что именно нужно.

У гостей

Непонятно, что выбрать под свой бюджет и не купил ли кто-то такой же подарок.

Наше решение

Одно событие со списком желаний и общей информацией о доступности подарков.

01 / Идея и возможности

Два участника одного события

Владелец управляет списком, гость выбирает подарок

Владелец

Регистрируется, создаёт событие, добавляет подарки и отправляет публичную ссылку.

Гость

Открывает ссылку без обязательной регистрации, бронирует подарок или указывает взнос.

Общий контекст

Дата, место, описание события и карточки желаний доступны на странице события.

Бронирование и сохранение сюрприза

Гости координируют выбор через общий статус

Без аккаунта

Гость указывает имя и секретное слово. Оно позволяет отменить свою бронь.

Один подарок — одна бронь

Сервер не позволяет двум участникам одновременно забронировать один обычный подарок.

Режим владельца

По умолчанию сервер скрывает от владельца сведения о брони. Просмотр можно включить отдельно.

02 / Технологии и устройство

Архитектура проекта

Клиент, сервер и хранилище отвечают за разные задачи

Браузер · React

Показывает страницы, формы и статусы. Отправляет действия пользователя на сервер.

API · FastAPI

Проверяет входные данные и права, выполняет правила работы с событиями и подарками.

Хранилище · SQLite и файлы

База сохраняет связанные записи. Загруженные изображения лежат отдельно на диске.

Связь компонентов

Клиент и API обмениваются данными по HTTP в формате JSON. Магазины и SMTP подключены к серверу.

Модель данных

Событие объединяет желания и действия участников

Пользователь и события

У одного пользователя может быть несколько событий. Каждое событие принадлежит одному владельцу.

Событие и подарки

Событие содержит подарки и собственные теги. Один подарок может иметь несколько тегов.

Подарок и участие

С подарком связаны бронь, взносы и вопросы. У обычного подарка возможна одна активная бронь.

Изображения

В базе хранятся сведения о файле и его владельце. Само изображение хранится на диске.

03 / Надёжность и результат

Доступ и защита аккаунта

Права проверяются на сервере при выполнении действия

Вход · JWT

Сервер проверяет подпись, срок действия токена и актуальность учётных данных.

Пароли · bcrypt

База хранит хеши. После смены пароля прежние токены входа перестают подходить.

Разделение прав

Управление событием доступно владельцу. Публичный токен даёт гостевой доступ к конкретному событию.

Почтовые ссылки

Одноразовые токены имеют срок действия. Сервер ограничивает частые запросы.

15 / 21
03 / Надёжность и результат

Согласованность действий

Сервер проверяет правила повторно перед сохранением

Одновременная бронь

Изменение статуса и создание брони проходят вместе. Два участника не получают одну и ту же бронь.

Цель совместного подарка

Взнос не может превысить остаток. Изменения подарка учитывают уже записанные суммы.

Ошибки и подтверждение

При отказе сервера интерфейс показывает ошибку. Удаление требует подтверждения пользователя.

Проверки проекта

Автоматические проверки охватывают ключевые правила

Серверные тесты

Бронирование, приватность, взносы, вопросы, архив и копирование, почта и импорт товаров

Клиентские проверки

GitHub Actions

Публикация приложения

Вход на сайт

По схеме развёртывания Nginx отдаёт файлы React и направляет запросы API в Uvicorn.
