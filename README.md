# Wishlist

Сервис для личных желаний, событий и выбора подарков. Владелец собирает список и делится им; гости могут забронировать подарок без регистрации, указав имя и секретное слово для отмены брони.

## Возможности

- Личные желания без привязки к событию, поиск по названию и собственным тегам, приоритет, отметка «Мне подарили».
- События с датой и временем начала, длительностью, местом и обложкой. Новые даты хранятся со смещением часового пояса; браузер показывает время по настройкам устройства. Даты, сохранённые раньше без пояса, сохраняют прежнее поведение.
- Автоматический архив после последнего дня события, копирование событий и сохранение неподаренных желаний при удалении.
- Публичные ссылки на событие и выбранные желания, QR-код, гостевые брони и совместные подарки с учётом обещанных взносов. Платежи через сайт не выполняются.
- Импорт доступных данных товара по ссылке. Маркетплейс может ограничить доступ, и тогда данные заполняются вручную.
- Подтверждение почты, восстановление пароля и добровольные напоминания о событии за неделю и за день для владельца и зарегистрированных гостей с бронью.

## Стек

React 19, React Router, Vite и Axios; FastAPI, Pydantic, SQLite и файловое хранилище изображений. Leaflet используется для выбора места, SMTP — для писем. Пароли и гостевые секретные слова хранятся как bcrypt-хеши.

## Локальный запуск

Нужны Python 3.10+ и Node.js, совместимый с Vite 8 (20.19+ или 22.12+). Из корня репозитория:

```bash
./run.sh
```

На Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт создаёт виртуальное окружение и `.env` с ключом JWT, устанавливает зависимости и запускает приложение. При повторных запусках уже установленные зависимости используются снова.

- Приложение: `http://localhost:5173`
- API: `http://127.0.0.1:8000`
- Документация API: `http://127.0.0.1:8000/docs`

Оба процесса останавливаются через Ctrl+C. У `run.sh` есть флаги `--backend-only`, `--frontend-only` и `--skip-install`.

### Запуск вручную

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Установите в .env случайный JWT_SECRET_KEY.
uvicorn app.main:app --reload
```

В другом терминале:

```bash
cd frontend
npm ci
VITE_API_URL=http://127.0.0.1:8000 npm run dev
```

На Windows используйте `.venv\Scripts\activate` для активации окружения. Для генерации ключа: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

## Настройки

Шаблон серверного окружения — `.env.example`. `JWT_SECRET_KEY` обязателен; `DATABASE_PATH`, `UPLOAD_DIR` и `CORS_ORIGINS` задают расположение базы и файлов и допустимые адреса фронтенда. Локальная SQLite-база создаётся при запуске. Данные и секреты `.env` не следует отправлять в Git.

`VITE_API_URL` задаёт адрес API при запуске или сборке фронтенда; для публикации используется `/api`. `VITE_MAP_TILE_URL` позволяет выбрать совместимый сервис тайлов карты; необходимо соблюдать условия выбранного провайдера и указывать атрибуцию.

Для почты настройте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USE_SSL`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` и `PUBLIC_API_URL`. Автоматические напоминания дополнительно включаются на сервере через `EVENT_REMINDERS_ENABLED=true`; пользователь должен подтвердить почту и включить их в профиле. Гостям без аккаунта письма не отправляются. Проверка запускается раз в час и использует локальную дату сервера; SMTP-приём не гарантирует доставку во входящие.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -q
cd frontend
npm run lint
npm test
npm run build
```

Серверные тесты используют отдельную тестовую базу. Дополнительно полезно проверить мобильные экраны и доставку почты в целевом окружении.

## Данные и доступ

Личные события и подарки доступны владельцу. Публичная ссылка открывает опубликованные данные любому её получателю. Подписанные ссылки на изображения ограничивают доступ, но это не сквозное шифрование: администратор сервера с доступом к базе и файлам технически может читать сохранённые данные.

У ранее созданных событий нет информации об исходном часовом поясе. Для новых событий сохраняется смещение на дату начала; при переводе часов во время многодневного события момент автоархивации может отличаться на час. Старые запросы без часового пояса поддерживаются для совместимости и не дают серверу надёжно определить прошедшее время.

## Публикация

GitHub Actions запускает workflow `Deploy` вручную из `main`: он проверяет сервер, собирает фронтенд и отправляет релиз на настроенный сервер. Настройка Nginx, секретов, SMTP и резервных копий выполняется в окружении сервера. Отправка ветки в Git сама по себе не публикует приложение.
